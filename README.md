###1. Экспериментальные замеры времени выполнения на виртуальной машине Java (JVM) подтвердили теоретические асимптотические оценки сложности всех исследованных алгоритмов.


###2. Операция прямого доступа к элементу массива по индексу демонстрирует константную сложность $O(1)$ (~2–2,5 нс), практически не зависящую от размера массива $N$, с незначительным ростом на больших объёмах из-за промахов кэша процессора (L1/L2).


###3. Бинарный поиск в отсортированном массиве показывает логарифмический рост времени $O(\log N)$: при увеличении входных данных в 12 800 раз время выполнения возрастает всего в ~4–5 раз, причём поиск отсутствующего элемента стабильно требует максимального числа итераций.


###4. Линейный поиск подтвердил зависимость времени работы от позиции искомого элемента: поиск первого элемента выполняется за константное время $O(1)$, поиск случайного элемента в среднем занимает вдвое меньше времени, чем поиск отсутствующего элемента, который проходит весь массив за $O(N)$.


###5. Алгоритм подсчёта элементов по условию имеет линейную сложность $O(N)$ во всех трёх случаях, однако при случайном распределении совпадений (~50%) время выполнения выше из-за частых ошибок предсказателя переходов процессора (*branch misprediction*).


###6. В самостоятельном исследовании алгоритма поиска максимума время во всех случаях также растёт линейно $O(N)$, но худший случай (возрастающий массив) работает медленнее лучшего (убывающий массив) из-за необходимости перезаписывать переменную максимума на каждой итерации.


###7. Использование предварительного прогрева JVM и усреднения по 5 сериям измерений позволило нивелировать влияние JIT-компиляции, загрузки классов и фонового шума операционной системы, обеспечив высокую воспроизводимость результатов.
